# Senior consultant

The optional twenty-third profile answers one bounded question from selected
published evidence. The coordinator keeps planning, implementation and acceptance.
All 22 executor profiles remain available with their shared publication protocol.
The consultant uses a separate access protocol and the same report publication.
See the [verification report](verification.md) for actual host outcomes, usage and limits.

## Risk-triggered transition use

Consultation is an optional coordinator decision at a work transition, not a
stage or gate. Consider one bounded consultation only when at least one
consequence trigger and at least one uncertainty trigger apply; otherwise proceed
without it. Consequences cover material architecture/public-tool/storage/security/
release/migration/multi-owner decisions, hard-to-reverse external/scope/
compatibility choices, contradictory repair-to-acceptance evidence or broad claims,
and replanning after repeated failure or surprise. Uncertainty covers material
alternatives, fact/hypothesis conflict or an untested critical assumption, no
discriminating check/evidence boundary, or a fresh view likely to change the
decision.

Routine/reversible/deterministic work, ordinary tests, already-decided detail,
phase/time/report existence alone, executor-evidence requests, unchanged packets,
consultation chains/sign-off/fixed counts and active incident recovery are
excluded. The consultation may run concurrently when safe, never blocks by rule,
and never transfers planning, steering, evidence interpretation, acceptance or
user communication. Its compact packet records the question, goal/constraints/
revision, transition/deadline, alternatives, facts/hypotheses, selected report
IDs and artifact versions, attempts/results, ownership boundaries, mutable
decision and requested check, without copied report bodies or private data. The
coordinator records triggers, selected report, decision, rationale, owner, next
check and whether advice changed the decision. Evaluate quality and overhead
against the unchanged baseline.

## Example complete cycle

An explorer publishes a report for artifact revision A: the response is stale,
but cache age and update timing have not been measured. The coordinator records
one question in the newest pipeline edition: should the cache be invalidated or
should the write path be repaired? It assigns Sol medium a compact packet with
the current requirement revision, that exact report ID, revision A, observed
attempts, and separately labelled hypotheses. Complete consultant instructions
are attached without conversation inheritance.

The consultant reads the selected report's necessary bounded pages. Its own
published report states that evidence is insufficient and asks a debugger to
compare the stored value, cache age and request timing, with distinct expected
results for each explanation. It neither reads source nor runs the check.

The coordinator records the recommendation and assigns the debugger. The new
report for revision B shows a correct stored value and an old cache entry. The
coordinator can continue the consultation with both exact report IDs and the new
question. The second consultation distinguishes the old uncertainty from the
new observations, recommends invalidation, and states what would overturn that
recommendation. This new evidence justifies the additional consultation.

The coordinator updates the pipeline, assigns the implementation and a focused
verification to executors, and accepts only after their published results prove
the requested behavior. Each edition records the question, consultant model and
effort, selected reports, conclusion report and coordinator decision.

## Models and access

Sol medium is the default, low is for narrow questions, and high is for harder
ones. Astra low/medium/high requires a justified deeper assessment. Native model
and effort choices are explicit and configurable per assignment; the main session
is unchanged. Repeating an unchanged question and evidence packet is prohibited.

The consultant may read the assignment and explicitly selected reports, edit its
own server-issued unpublished draft, publish it, and request missing information
through its native parent. It cannot run commands, inspect project or network
state, browse the report catalogue, spawn agents, or change the pipeline.

These role boundaries are instructions plus a development audit of observed
calls, not a tool sandbox. The server enforces task isolation and draft ownership.
The audit rejects terminal/project access, foreign or pipeline draft patches,
unapproved models, and agent messaging outside the parent. Full selected-report
scope remains instruction-enforced. An unavailable host or hidden invocation
leaves the corresponding criterion unverified.

The native name `senior_consultant` plus explicit Sol medium and no inherited
conversation allow the audit to verify the default route despite an encrypted
assignment. Hidden packet contents are still unverified; this exception does not
prove escalation rationale or permit other opaque model routes. Discovery reads
one complete missing tool declaration at a time. Publication uses only declared
fields, and copied evidence hashes must match their authoritative receipts.
