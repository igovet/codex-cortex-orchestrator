# Outcome-driven incident coordination

The compact orchestrator loads incident, routing, live-host, release and recovery
details only when needed. The coordinator keeps the causal model and outcome
across specialist handoffs. Investigators resolve concrete uncertainties, developers
implement and self-test, and independent reviewers/verifiers assess nontrivial or
consequential changes. A low-risk edit may use one executor; no fixed three-stage
pipeline or numerical agent cap is imposed. Timeouts do not replace assignment
owners. Models are selected separately for each role under the existing policy.

Task-wide advisory governance is returned by every public tool and restored in
recovery hints. Minimal narrows low-risk work; light covers component impact and
independent checking of nontrivial edits; full covers consequential end-to-end,
integration and rollback evidence. It changes model decisions, not permissions or
automatic model selection. The pipeline records its concrete effect. Unavailable
projection is diagnostic and cannot roll back successful work. Replaying an old
delivery does not roll back current governance. Normal/cortex participation remains
independent of the selected depth.

The current pipeline contains the full path, snapshot, identity namespaces,
safe-to-working transition, rollback, facts/hypotheses and unchecked predicates.
Confidence advances from hypothesis through isolated_root_cause to
end_to_end_root_cause only with supporting evidence. Two distinct unknown live
failures require re-baseline before another rollout. One production-shaped rehearsal
covers success, replay, conflict, tamper, schema/type checks, rollback and counted
provider calls. Missing local testing limits production to read-only preflight.

The optional incident_decision template block groups the decision and references
the existing six advisory fields. Runtime incident_quality evaluates normalized
observations with bounded input and value-free output. It never routes, denies or
accepts work. Invalid or oversized input returns verified=false. Empty diagnostics
are not proof of a completed task; actual trace evidence is still required.

Nine advisory signals identify premature cause claims, unchecked downstream paths,
production-first testing, repeated live failure without re-baseline, duplicate checks,
pipeline churn, unjustified agents, premature ETA and unchanged wait messages.
Behavioral qualification treats these as process failures; runtime remains advisory.

Run `PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q tests/test_incident_quality.py`.
The sanitized executable fixture tests read-only snapshot, receipt epochs, identity
namespaces, activation, wrong key types before mutation, replay/conflict/tamper,
rollback, and reduction/closure under DENY using a fake provider. It is an in-memory
contract model, not proof of real Redis/Lua or LLM behavior. Real CLI/Desktop incident
qualification remains required on an unchanged candidate after offline checks.

`python3 -B scripts/incident_evaluation.py TRACE.json` evaluates a bounded array
of normalized observations. Process violations or missing user-boundary evidence
return exit 1 only to this offline evaluator; they never stop a running Cortex task.
Trace provenance must be established separately. A synthetic passing trace is not
a live model evaluation or production acceptance.

Target metrics: continuous coordination and justified specialist assignments, at most five major pipeline editions,
zero unchanged wait messages or premature definitive claims, no duplicate review
without delta, one cohesive change and one rollout after rehearsal. ETA requires a
complete remaining critical path and expires after a new class of failure.
