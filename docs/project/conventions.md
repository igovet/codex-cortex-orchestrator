# Conventions

## Authority and scope

- Installable behavior lives below plugins/cortex. Repository documents and
  AGENTS.md are development support, not another installed contract.
- Activate orchestration only on explicit selection; ordinary complexity does
  not activate it. The normal route leaves orchestration.
- Use the installed skill as supplied by the host. Never invent a second
  repository-level skill, hidden tool or skill-resource lookup.
- The LLM owns semantics, decomposition, profiles, model/effort selection,
  ready-node scheduling and evidence interpretation. The core guards typed
  transitions, not autonomous scheduling.
- The root coordinator delegates project inspection, changes and verification.
  Its only direct project-read exception is the installed skill's known-index
  and relevant-linked-page routing boundary.
- Worker discovery prefers Codebase Memory bound to the canonical root. An
  unavailable or insufficient result permits one bounded safe fallback.
- The live twenty-operation catalogue owns every argument shape and limit.
  Skills, worker prompts and live workloads contain semantics, not field
  tutorials or sample MCP payloads.

## Contracts, graphs and assignments

- Preserve every independently actionable outcome with complete acceptance,
  constraints and expected checks. Preserve original user text separately.
- Fresh task opening precedes governance assessment and the first assignment.
  Minimal/light complete plans may be informational; complexity is not an
  approval trigger.
- Minimal work uses a generated complete-contract graph. Nontrivial work uses
  planner-owned candidates and independent semantic validation.
- Contribution ownership is unique. Composite outcome completion and many-to-many
  independent verification are explicit graph relations.
- Dependencies provide required capabilities. Audit prerequisites must be
  acceptable before dispatch; missing implementation is not a reason to launch
  an auditor that will predictably return partial.
- Select exact current semantic node keys. The server derives immutable scope,
  checks and predecessor evidence; no second prose assignment is accepted.
- Native slot capacity does not change readiness. Multiple compatible readers
  can run in parallel; one project mutator excludes conflicting readers and
  mutators. Do not replace this barrier with a general single-worker limit.
- A successful non-replayed assignment receives one exact unchanged native
  spawn. Never reconstruct bootstrap, match by launch order or replay success.
- A fresh worker consumes only its own assignment first. Project work follows
  terminal consumption, then one purpose-bound publication and stop.
- Planning nodes publish plans, documentation nodes publish documentation
  assessments and all other nodes publish results. Profile and edit count do
  not select terminal kind.
- Result/documentation coverage is canonical observed evidence. Plans contain
  expected checks; artifact commitments identify observations without a second
  narrative or fabricated success.

## Decisions and progress

- Complete decision alternatives belong in one independently validated candidate
  family. One direct response selects a branch, applies its complete delta,
  advances revision and approves only that graph atomically.
- Pre-plan steering is for a genuine choice necessary to construct responsible
  alternatives, not tool coverage. Empty semantic changes are invalid.
- Direct user changes commit immediately, including while another question or
  old worker is pending. Do not request a second confirmation.
- Approval fulfills its current decision boundary. Informational replans do not
  ask again unless new material risk/authority or explicit renewed review
  requires a fresh packet.
- Changed candidate, validation, artifact/barrier or assessment evidence
  invalidates an unanswered old plan packet without blocking current replanning.
- In-contract defects use validated finite remediation/regression policies.
  Successful regression restores only proven capabilities and never rewrites
  the original failed report. Scope/authority/risk changes cannot silently use
  ordinary correction authority.
- Non-progress and exhausted budgets remain explicit incomplete states, not
  endless workers or invented success. Recoverable internal problems do not
  become unnecessary user questions.

## Artifacts and recovery

- Workers run the declared deterministic Git/path-manifest fingerprint.
  Read-only start/end observations match one sealed target generation.
  Mutation seals a successor; old dependent evidence remains historical.
- Snapshot conflict is a non-publication result and raises reconciliation.
  Steering likewise invalidates old authority before native interruption.
- Match returned protected task names to supported native observations.
  The coordinator interrupts stale workers; hooks and MCP cannot do it
  asynchronously. Reconciliation observes actual remaining writes.
- Revised planning and execution wait for native quiescence and a sealed
  reconciliation baseline. Do not claim cancellation reverted files.
- On recovery, current state precedes required terminal continuation reads.
  Timeline serves an actual chronology/audit need, never continuation lookup.
- Loss needs complete supported native evidence and no finalized publication.
  Timeout, silence, an unavailable native projection or a stop hook alone
  cannot authorize replacement.
- No worker leaves an unowned background mutator after its final fingerprint.
  Closure describes the latest observed generation, not a nonexistent atomic
  filesystem seal across user review.

## Models, communication and closure

- Default most work to Luna through max. Native spawn omits its model override;
  qualification verifies the host default is Luna.
- Reserve explicit Terra for genuinely complex planning/architecture and
  explicit Sol for rare materially risky security work. Effort is explicit and
  never above max; ultra is not an orchestration route.
- Packaged profiles are immutable assignment policy, not native agent types,
  automatic model choices or authority grants.
- Keep worker engineering narrative English and coordinator presentation in
  the user's language. Preserve exact user evidence in designated fields.
- Use complete decision-ready packets and verified server-issued Markdown links.
  Missing plan views require projection repair, not a reconstructed path.
- Documentation edits precede final verification. Read-only documentation
  impact and final verification bind the same latest sealed generation.
- Present the current result, risks and unrun checks, then open the mandatory
  final closure review. Only direct current close authorizes closure.
  Prior plan approval or advance automatic-close instructions are insufficient.

## Storage and development

- Current schema only: reject old/unknown layouts and formats without migration
  or fallback. Never touch historical or stable user installations.
- Commit transitions, events and server-derived receipts atomically.
  Ambiguous identical retries reconcile; changed input conflicts.
- Keep private SQLite, backups, observations and derived views outside the
  project. Never use Markdown as ledger authority or expose raw diagnostics.
- Operator maintenance stays outside MCP, uses exact private targets and
  confirmations, and restores only after independently verified offline status.
- Use python3, apply_patch and the smallest relevant checks before broad
  validation. Do not run release-sensitive suites concurrently in one checkout.
- Refresh candidate cache stamps through scripts/cortex-dev, only in the isolated
  development runtime. Keep semantic version frozen for this hardening work.
- Ordinary interactive CLI tests use the exact supported tmux transport.
  Never substitute codex exec, synthetic leases or source-MCP tests for native
  live results. The operator observes the composer, activation receipt and every
  worker event before claiming acceptance.
- Full Desktop qualification follows successful CLI on the unchanged payload;
  a payload edit invalidates both. Follow the full
  [qualification ladder](typed-orchestration-integrity.md#10-qualification-ladder).
- Update the [Completion checklist](typed-orchestration-integrity.md#11-completion-checklist)
  after each verified step. Keep unrun and failed gates explicit.
- Re-read README, SECURITY and affected documentation after behavior/interface
  changes; check links, commands and diagrams against executable sources.
