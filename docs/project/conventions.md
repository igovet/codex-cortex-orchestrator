# Conventions

<!-- GENERATED:START -->
- The plugin’s machine-readable contracts live under [plugins/cortex](../../plugins/cortex/), including the manifest, MCP configuration, profile registry, and hook configuration.
- [profiles.json](../../plugins/cortex/profiles.json) is the canonical machine-validated source for all 21 exact profile names, descriptions, sandboxes, automatic/manual route categories, gates, `select_when`, `avoid_when`, ordered implementation rules, 13 gate-specific briefing defaults, and shared report fields. Profile TOMLs must match its identity, description, and sandbox. Generated worker prompts layer the selected playbook, overall task context, and current gate mission/criteria; explicit coordinator overrides win over gate defaults.
- Automatic implementation routing uses bounded explicit signals from objective, requirements, acceptance criteria, scope, allowed paths, and verification. It applies the ordered specialist rules from `profiles.json` and uses `general` only as the conservative fallback. Planner/explorer evidence is advisory: the coordinator alone decides whether it justifies changing not-yet-started future waves, and records a concise reason. Planner and explorer prompts and the root orchestrator skill receive the generated canonical roster.
- The compact public worker `profile` field enumerates all 21 canonical names; legacy aliases are compatibility input only. A phase/profile mismatch is rejected before ledger writes. Dispatch metadata exposes phase, profile, capability, sandbox, and selection reason separately from unchanged native call arguments.
- `cortex/report/v1` payloads contain exactly `summary`, `findings`, `questions`, `changed_files`, `tests`, `evidence`, `uncertainty`, and `next_action`; the server sanitizes report data before persistence. See [cortex.py](../../plugins/cortex/scripts/cortex.py).
- Report persistence is bounded: one report is at most 64 KiB; an attempt can publish 32 reports; a task can publish 256 reports totaling at most 1 MiB; and an attempt can receive at most 256 explicit context grants. Stranded-report recovery allocates a new record and never overwrites an authoritative record.
- Ledger, report-bus, journal, and lifecycle-telemetry paths reject symlink traversal and require regular-file targets before reads or writes. Report JSON is authoritative; `reconcile_report_bus` repairs derived indexes, receipts, and Markdown after an interrupted multi-file publication.
- Observational metrics accept only nonnegative integer token/elapsed fields and finite nonnegative costs. Their retained tail is bounded to 1,000 events or 512 KiB and increments `telemetry_dropped` when old entries are evicted.
- The public MCP surface exposes exactly five tools: three coordinator lifecycle tools—`start_orchestration`, `continue_orchestration`, and `manage_orchestration`—plus worker-only `record_report` and coordinator-only `read_worker_report`. Normal-flow calls require an exact absolute `project_root`; one MCP process may independently serve multiple project roots. Start builds the task and first wave, worker reports are persisted and read by compact ref, continue advances one relative `step`, and manage covers recovery and rare lane/resource/question operations. Native `spawn_agent` and user-authorized `create_thread` remain host calls, not public MCP tools.
- The coordinator builds or consciously accepts the initial pipeline, follows the returned snapshot by default, and alone changes future waves when verified evidence materially changes the work; planner/explorer recommendations are advisory. Human aliases such as `implement` and `build_verification` normalize to `implementation` and final `close`, respectively, and do not create retry waves.
- A worker writes the exact eight-field report through `record_report`, then returns only `REPORT_RECORDED report_ref=<value>` plus at most a two-sentence summary, or the exact tool error. The coordinator reads the ref through `read_worker_report` and advances with it. Inspect exposes `available_reports` when persistence succeeded before an interrupted native acknowledgement.
- Codebase Memory is optional worker tooling. If available, the worker resolves the project by exact root with `list_projects`, prefers graph/architecture/trace operations for discovery and impact, confirms consequential facts in source/tests, and falls back once without looping when the service or index is unavailable or stale. The coordination-only root never uses it to inspect the target project.
- During active Cortex orchestration, the main/root agent is coordination-only: it may use lifecycle calls, exact returned dispatches, waiting, report evaluation, user communication, and safe recovery, but must never inspect, search, read, edit, patch, build, test, or run the target project. Workers own every project operation, and the root remains idle while they run. `SessionStart` and every public v3 `next_action` reassert this lock.
- Structured public v3 `ok: false` validation and recovery responses are caller-correctable protocol outcomes, not MCP server exceptions, and are not appended to `~/.codex/logs/cortex-tool-errors.jsonl`. Raised MCP-boundary exceptions remain redacted and logged.
- Mutating v3 calls use server-owned request-digest receipts for idempotent replay. An identical retry replays; a changed payload, stale step, duplicate slot, or missing slot is rejected before partial writes. Public schemas do not require submission, task, wave, attempt, or host metadata. Profiles and aliases are preloaded/validated when the MCP server starts.

- Repository validation and smoke scripts use `python3`; shell scripts use Bash with strict mode. See [validate-cortex-marketplace.py](../../scripts/validate-cortex-marketplace.py) and [sync-cortex.sh](../../scripts/sync-cortex.sh).
