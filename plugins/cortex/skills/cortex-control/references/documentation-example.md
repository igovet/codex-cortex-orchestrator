# Documentation report example

Use this as a content guide, not a required structure. Replace placeholders with
observed task facts; omit irrelevant sections, add useful ones and change their
order when helpful. Never copy example placeholders or imply checks were run.
Every profile uses the common Markdown writer; this file defines no tool arguments.

## Example Markdown

```markdown
# Documentation update: <verified change>

## Impact and scope

<Which behavior, interface, command, decision or ownership changed and which docs own it.>

## Updates and preservation

| Document | Updated content | Preserved manual material |
| --- | --- | --- |
| <Path> | <Change grounded in source> | <Relevant unchanged authored sections> |

## Supporting evidence and checks

<Source/test/report references; link, anchor, command and terminology checks actually
performed. Separate planned checks from successful, failed and unrun checks.>

## Coverage and gaps

<Assigned documentation coverage, missing pages, contradictions or unsupported claims.
For harvest, include the relevant census and no-change comparison evidence when assigned.>

## Follow-up

<Remaining documentation or implementation work, risks and recommended owner.>
```
