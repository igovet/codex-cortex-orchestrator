# Investigation and design report example

Use this as a content guide, not a required structure. Replace placeholders with
observed task facts; omit irrelevant sections, add useful ones and change their
order when helpful. Never copy example placeholders or imply checks were run.
Every profile uses the common Markdown writer; this file defines no tool arguments.

## Example Markdown

```markdown
# Findings: <assigned question>

## Scope and evidence consulted

<Bounded question, relevant report references, documentation routes and source paths.>

## Findings

| Finding | Supporting evidence | Confidence or gap |
| --- | --- | --- |
| <Observed behavior or dependency> | <Source/test/inspection> | <Established or inference> |

## Analysis and alternatives

<Root cause, design trade-offs or affected paths, as appropriate to the assignment.
Keep conclusions distinct from assumptions and do not broaden the work.>

## Checks and limitations

<Actual commands/observations and results. Note unavailable Codebase Memory and
the bounded fallback only when that happened. Include unrun checks and unknowns.>

## Recommended next work

<Concrete follow-up, suitable owner, dependencies and any question for the coordinator.>
```
